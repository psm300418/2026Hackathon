# 개인 피부 데이터 앱 기획서

> 문서 상태: 초안  
> 목적: 프로젝트의 문제, 사용자, 핵심 기능과 범위를 정의하고 이후 Architecture, Design, Security, Backlog 문서 작성의 기준으로 사용한다.

---

## 1. 문제 정의

새로운 화장품을 사용하거나 기존 제품을 바꾼 뒤 피부 상태가 변하더라도, 사용자는 어떤 제품이나 성분이 변화와 관련되어 있었는지 정확히 파악하기 어렵다.

피부 변화에는 제품뿐 아니라 수면, 스트레스, 식습관, 생리주기, 날씨 등 여러 요인이 함께 작용할 수 있으며, 변화가 즉시 나타나지 않는 경우도 있다. 또한 여러 제품을 동시에 사용하거나 교체하기 때문에 특정 제품 또는 성분과 피부 변화의 관계를 기억만으로 판단하기 어렵다.

현재 사용자는 제품을 사용한 경험을 후기나 기억에 의존해 판단하는 경우가 많고, 시간이 지나면 어떤 제품을 언제 사용했는지, 당시 피부 상태가 어땠는지에 대한 개인 데이터가 남지 않는다.

이 서비스는 사용자가 제품 사용 기록, 피부 상태, 피부 사진, 생활 요인을 지속적으로 기록하도록 하고, 축적된 데이터를 바탕으로 피부 변화와 반복적으로 함께 나타나는 제품 및 성분 후보를 좁혀주는 것을 목표로 한다.

### 핵심 문제

- 여러 제품을 동시에 사용하면 피부 변화와 관련된 요인을 구분하기 어렵다.
- 과거 경험을 기억에 의존하기 때문에 사용 시점과 피부 상태를 정확히 연결하기 어렵다.
- 기록 과정이 번거로우면 장기적인 개인 데이터가 쌓이지 않는다.
- 단 한 번의 피부 변화만으로 특정 제품이나 성분을 원인으로 판단하기 어렵다.
- 개인에게 맞는 제품과 성분에 대한 정보가 장기적인 개인 데이터로 축적되지 않는다.

## 2. 서비스 개요

본 서비스는 **스마트폰 애플리케이션과 백엔드 서버로 구성된 개인 피부 데이터 관리 서비스**이다.

사용자는 자신이 사용한 화장품, 제품 성분, 피부 상태, 피부 사진과 필요한 생활 요인을 날짜별로 기록한다.

서비스는 이 데이터를 장기간 축적하고, 제품 사용 시점과 이후 피부 상태 변화를 비교하여 사용자에게 반복적으로 긍정적 또는 부정적 피부 변화와 함께 나타나는 제품 및 성분 후보를 보여준다.

서비스의 목적은 피부 질환을 진단하거나 특정 성분을 원인으로 단정하는 것이 아니라, 사용자의 개인 기록을 기반으로 **관련 가능성이 있는 제품·성분·생활 조건을 근거와 함께 좁혀주는 것**이다.

### 서비스 핵심 가치

> 한 번의 피부 진단이 아니라, 기록할수록 근거가 쌓이는 나만의 피부 사용설명서.

서비스의 핵심 자산은 제품 추천 목록이 아니라 시간이 지날수록 축적되는 **개인별 제품·성분–피부 반응 데이터**이다.

## 3. 대상 사용자 및 역할

### 주요 사용자

새로운 화장품을 자주 사용하거나 여러 제품을 사용하면서 다음과 같은 궁금증을 가진 사람을 주요 사용자로 한다.

- 어떤 제품이 자신의 피부에 잘 맞는지 알고 싶은 사용자
- 어떤 성분이 자신의 피부 변화와 관련되어 있는지 알고 싶은 사용자
- 화장품 사용 후 피부 변화를 체계적으로 기록하고 싶은 사용자
- 단기적인 피부 진단보다 장기적인 피부 상태 변화를 관리하고 싶은 사용자
- 피부과 상담 등에 활용할 수 있도록 자신의 피부 기록을 정리하고 싶은 사용자

### 사용자 역할

초기 버전에서는 일반 사용자 단일 역할을 기본으로 한다.

향후 서비스 확장 시 사용자 동의를 전제로 피부 기록을 확인할 수 있는 전문가용 기능을 별도로 고려할 수 있다.

## 4. 사용자 시나리오

### 4.1 최초 이용

1. 사용자는 회원가입을 진행한다.
2. 회원가입 후 초기 피부 상태 및 피부 특성을 파악하기 위한 설문을 진행한다.
3. 사용자는 현재 사용 중이거나 과거에 사용했던 화장품을 등록한다.
4. 과거 제품에 대해 기억나는 피부 반응이 있다면 참고 데이터로 함께 기록할 수 있다.
5. 자주 사용하는 제품은 아침·저녁 등의 스킨케어 루틴으로 등록할 수 있다.

### 4.2 일일 기록

1. 사용자는 실제로 사용한 제품 또는 미리 등록한 루틴을 선택한다.
2. 사용 시간은 가능한 경우 자동으로 기록한다.
3. 사용자는 간단한 설문을 통해 그날의 피부 상태를 기록한다.
4. 필요한 경우 피부 사진을 함께 등록한다.
5. 필요한 경우 수면, 스트레스 등 피부 변화에 영향을 줄 수 있는 생활 요인을 함께 기록한다.

### 4.3 데이터 축적

서비스는 다음 데이터를 날짜와 시간 흐름에 따라 축적한다.

- 사용한 제품
- 제품의 성분 정보
- 제품 사용 시점
- 피부 상태
- 피부 사진
- 생활 요인
- 이상 반응 및 특이사항

과거 사용 경험과 서비스 가입 이후 직접 기록된 데이터는 구분하여 관리한다.

과거 경험은 참고 데이터로 사용하고, 서비스 가입 이후 지속적으로 기록된 데이터는 분석의 주요 근거로 활용한다.

### 4.4 개인 분석

사용자는 분석 탭에서 현재까지 쌓인 기록을 바탕으로 개인 분석을 요청할 수 있다.

서비스는 기록이 충분하지 않더라도 분석을 수행하되, 데이터가 부족한 경우 신뢰도가 낮다는 점과 추가 기록이 필요하다는 점을 명확하게 안내한다.

분석 요청 시 서비스는 다음 내용을 비교한다.

- 특정 제품 사용 이후 피부 변화가 반복되었는지
- 같은 성분이 포함된 서로 다른 제품에서도 비슷한 변화가 나타났는지
- 해당 제품 또는 성분을 사용했지만 피부 변화가 없었던 경우가 있었는지
- 피부 변화가 나타나기까지 일정한 시간 차이가 있었는지
- 수면 부족, 스트레스 등의 생활 요인이 함께 나타났는지

분석 결과는 특정 성분을 원인으로 확정하지 않고, 현재 데이터에서 관련 가능성이 높은 제품 및 성분 후보를 근거 수준과 신뢰도 안내와 함께 제시한다.

### 4.5 지속 사용

사용자가 기록을 계속할수록 개인별 제품·성분과 피부 반응 데이터가 축적되고, 분석 결과는 점차 구체화된다.

데이터가 부족하거나 다른 요인의 영향을 배제하기 어려운 경우 서비스는 이를 명확하게 표시하고 추가로 필요한 기록을 안내한다.

## 5. 핵심 기능

### 5.1 회원 관리

- 회원가입
- 로그인
- 로그아웃
- 사용자 계정 관리

### 5.2 초기 피부 상태 조사

회원가입 직후 사용자의 초기 피부 상태를 파악하기 위한 설문을 진행한다.

예시 항목:

- 평소 건조함
- 평소 유분
- 붉음
- 트러블 빈도
- 주요 피부 고민
- 현재 사용 중인 제품

초기 설문은 사용자를 하나의 고정된 피부 타입으로 단정하기 위한 것이 아니라 이후 기록과 비교하기 위한 초기 기준점으로 활용한다.

### 5.3 제품 등록

사용자는 현재 사용 중이거나 과거에 사용했던 제품을 등록할 수 있다.

제품 등록은 제품명 검색을 기본 흐름으로 한다. 서비스는 먼저 자체 데이터베이스에서 제품을 검색한다.

검색 결과가 있는 경우 사용자는 해당 제품을 선택해 등록한다. 검색 결과가 없거나 성분 정보가 부족한 경우 사용자는 제품명, 브랜드, 제품 종류와 성분표 사진을 제출할 수 있다.

서비스는 성분표 사진에서 텍스트와 성분 후보를 AI로 추출하고, 사용자는 추출 결과를 직접 확인하거나 수정한 뒤 저장한다. 사용자가 최종 확인한 제품 정보와 성분 정보는 앱의 공용 제품 데이터베이스에 `community` 상태로 등록되어 이후 다른 사용자의 제품 검색 결과에 노출될 수 있다.

성분표 사진 원본은 제품 등록을 위한 텍스트 추출에만 사용하고 저장하지 않는다.

제품에 대해 다음과 같은 정보를 관리한다.

- 제품명
- 제품 종류
- 제품 성분
- 사용 여부
- 사용 시작 시점
- 과거 사용 여부
- 기억나는 피부 반응

화장품의 정확한 성분 배합비가 공개되지 않은 경우 임의로 추정하지 않는다.

### 5.4 스킨케어 루틴 등록

사용자는 반복적으로 사용하는 제품을 하나의 루틴으로 등록할 수 있다.

예:

- 아침 스킨케어
- 저녁 스킨케어

루틴을 활용해 매일 제품을 하나씩 입력해야 하는 불편을 줄인다.

### 5.5 제품 사용 기록

사용자는 매일 실제로 사용한 제품 또는 루틴을 기록한다.

- 사용 제품
- 사용 시각
- 사용 루틴
- 필요 시 메모

기록 과정은 장기간 사용이 가능하도록 최대한 빠르고 간단하게 구성한다.

### 5.6 일일 피부 상태 기록

사용자는 간단한 설문을 통해 현재 피부 상태를 기록한다.

예시 항목:

- 건조함
- 유분
- 붉음
- 트러블

각 항목은 일정한 척도로 기록하여 날짜별 변화를 비교할 수 있도록 한다.

### 5.7 피부 사진 기록

사용자는 피부 상태를 사진으로 기록할 수 있다.

가능한 경우 동일한 각도와 비슷한 조명에서 촬영하도록 안내한다.

피부 사진은 분석을 보조하는 데이터로 사용하며, 사진 하나만으로 피부 상태의 원인이나 질환을 판단하지 않는다.

### 5.8 생활 요인 기록

필요한 경우 피부 상태에 영향을 줄 가능성이 있는 생활 요인을 기록한다.

초기 MVP에서는 기록 부담을 줄이기 위해 최소한의 항목부터 제공한다.

예:

- 수면 상태
- 스트레스 수준
- 특이사항

### 5.9 개인 피부 반응 분석

사용자는 분석 탭에서 현재까지 축적된 데이터를 바탕으로 제품 사용과 피부 상태 변화 사이의 반복 패턴 분석을 요청할 수 있다.

분석에 활용할 수 있는 주요 요소:

- 제품 노출 횟수
- 특정 성분 노출 횟수
- 피부 변화 발생 횟수
- 제품 사용과 피부 변화 사이의 시간 차이
- 반복 반응
- 무반응 사례
- 생활 요인 중첩

분석 결과는 다음과 같은 형태로 표현한다.

- 관련 가능성이 높은 제품 및 성분 후보
- 긍정적 의심 성분 후보 최대 5가지
- 부정적 의심 성분 후보 최대 5가지
- 근거 수준: 강함, 중간, 약함, 데이터 부족
- 긍정적 변화 또는 부정적 변화와 함께 나타난 반복 패턴
- 제품을 사용했지만 변화가 없었던 무반응 사례
- 수면 부족, 스트레스 등 함께 기록된 생활 요인
- 현재 분석의 한계와 추가로 기록하면 좋은 항목

긍정적 의심 성분과 부정적 의심 성분은 모두 사용자 기록에 기반한 근거와 함께 설명하며, 실제 원인 또는 치료 판단으로 표현하지 않는다.

### 5.10 AI 기반 인사이트

AI는 분석된 데이터를 사용자가 이해하기 쉬운 형태로 설명하는 핵심 기능이다.

예:

- 긍정적인 피부 변화와 반복적으로 함께 나타난 성분 후보
- 부정적인 피부 변화와 반복적으로 함께 나타난 성분 후보
- 특정 제품 사용 후 나타난 반복 패턴
- 현재 데이터의 근거 수준
- 분석을 위해 추가로 필요한 기록

AI는 특정 성분이나 제품이 피부 변화의 원인이라고 단정하지 않는다.

기록이 부족한 경우에도 AI는 현재 기록 안에서 가능한 범위의 요약과 후보를 제시하되, 신뢰도가 낮고 추가 기록이 필요하다는 점을 함께 설명한다.

AI 분석 결과는 긍정적 의심 성분 후보 최대 5가지와 부정적 의심 성분 후보 최대 5가지를 포함할 수 있으며, 각 항목에는 관련 기록, 반복 여부, 무반응 사례, 생활 요인 중첩 여부 등 근거를 함께 표시한다.

- 기록 알림

## 7. 핵심 비즈니스 규칙

### 7.1 분석 원칙

- 한 번의 피부 변화만으로 특정 제품 또는 성분을 원인으로 판단하지 않는다.
- 같은 성분이 포함된 서로 다른 제품에서 비슷한 반응이 반복되는지 확인한다.
- 제품을 사용했지만 피부 변화가 나타나지 않은 사례도 함께 분석한다.
- 제품 사용과 피부 변화 사이의 시간 차이를 고려한다.
- 수면 부족, 스트레스 등 다른 생활 요인이 함께 발생했는지 확인한다.
- 데이터가 충분하지 않은 경우 분석 결과에 불확실성을 표시한다.

### 7.2 AI 역할

AI는 다음 역할을 담당할 수 있다.

- 제품 성분표 사진에서 텍스트와 성분 후보 추출
- 성분명 및 단위 정규화
- MFDS 성분 마스터와 성분 후보 매칭
- 사용자 기록을 바탕으로 필요한 추가 질문 생성
- 분석 결과를 사용자가 이해할 수 있도록 설명
- 추가로 기록하면 좋은 항목 안내

AI는 분석 데이터나 성분표 사진에 존재하지 않는 내용을 임의로 사실처럼 생성하지 않는다. AI가 추출한 제품 성분은 사용자의 최종 검토와 확인을 거친 뒤 저장한다.

### 7.3 안전 원칙

서비스는 의료 진단 또는 치료를 제공하는 것을 목적으로 하지 않는다.

따라서 다음 표현과 기능을 피한다.

- 특정 피부 질환을 확정적으로 진단
- 특정 제품 또는 성분을 피부 문제의 확정 원인으로 표현
- 치료 방법 또는 의약품 사용을 직접 지시
- 데이터가 부족함에도 확정적인 결과 제공

필요한 경우 사용자가 전문가 상담을 고려할 수 있도록 안내한다.

### 7.4 데이터 원칙

- 과거 기억에 의존한 경험과 서비스 가입 이후 직접 기록된 데이터를 구분한다.
- 성분의 정확한 함량을 알 수 없는 경우 임의로 추정하지 않는다.
- 사용자 데이터가 많아질수록 분석 근거가 강화되도록 설계한다.
- 피부 사진과 건강 관련 기록은 민감한 정보로 간주하고 필요한 범위에서만 수집한다.
- 피부 사진, 피부 상태, 생활 요인 기록 수집 시 사용자에게 수집 목적을 명확히 안내하고 동의를 받는다.
- 사용자는 자신의 기록과 사진을 삭제할 수 있어야 한다.
- 향후 사용자가 자신의 기록을 내보낼 수 있는 기능을 고려한다.
- AI 분석에 필요한 데이터만 백엔드와 AI API에 전달하며, 불필요한 개인정보는 포함하지 않는다.
- 회원 탈퇴 시 사용자 기록과 사진의 처리 방식을 명확하게 정의한다.

## 8. 범위 및 제외 사항

### 8.1 초기 MVP 범위

초기 버전에서는 다음 흐름이 정상적으로 동작하는 것을 우선 목표로 한다.

**회원가입 → 초기 피부 설문 → 제품명 검색 기반 제품 등록 → 제품 사용 기록 → 일일 피부 상태 기록 → 사진 및 생활 요인 기록 → 개인 데이터 축적 → 분석 탭에서 AI 기반 제품·성분 관련 패턴 분석 요청**

AI 기반 분석과 인사이트 제공은 해커톤 프로토타입의 핵심 기능으로 포함한다.

### 8.2 MVP 성공 기준

초기 MVP는 다음 조건을 만족하면 성공으로 본다.

- 사용자가 제품명 검색 또는 직접 입력을 통해 제품을 등록할 수 있다.
- 사용자가 제품 사용 기록과 일일 피부 상태 기록을 입력하고 저장할 수 있다.
- 사용자가 저장된 데이터를 바탕으로 분석 탭에서 AI 분석을 요청하고 결과를 확인할 수 있다.

### 8.3 초기 버전에서 제외하는 기능

다음 기능은 초기 MVP의 필수 범위에 포함하지 않는다.

- 피부 질환 자동 진단
- 치료 방법 추천
- 의약품 처방 또는 복용 지시
- 제품 판매
- 사용자 데이터를 외부 업체에 판매하는 기능
- 전문가용 B2B 대시보드
- 복잡한 커뮤니티 기능
- 제품 인기 순위 중심의 추천 서비스

향후 사용자 검증 결과에 따라 별도의 기능으로 검토할 수 있다.

## 9. 기술적 제약 및 개발 방향

### 기본 시스템 구성

서비스는 다음 두 영역으로 구성한다.

- 스마트폰 애플리케이션
- 백엔드 서버

스마트폰 애플리케이션은 사용자의 제품 사용 기록, 피부 상태 설문, 피부 사진 등록 및 분석 결과 확인을 담당한다.

백엔드 서버는 사용자 데이터 저장, 제품 및 성분 데이터 관리, 피부 기록 저장, 분석 로직 및 AI 기능 연동을 담당한다.

### 세부 기술 스택

초기 해커톤 프로토타입의 기술 스택은 다음과 같이 정한다.

- Android 프론트엔드: Kotlin + Jetpack Compose
- 백엔드: TypeScript + Node.js + Express
- 데이터베이스: Supabase PostgreSQL
- 이미지 저장: Supabase Storage
- 인증: Supabase Auth, 백엔드에서 사용자 JWT 검증
- AI 연동: OpenAI API, 백엔드 서버에서 호출
- 외부 데이터 연동: MFDS 화장품 원료성분정보 API 기반 성분 마스터 연동
- 프로젝트 저장소 구성: Android, Backend, docs를 포함한 단일 GitHub monorepo

## 12. 핵심 사용자 경험

이 서비스는 한 번의 사진이나 한 번의 설문으로 사용자의 피부를 판단하는 서비스가 아니다.

처음에는 사용자의 피부에 대해 알고 있는 정보가 많지 않지만, 사용자가 제품 사용과 피부 상태를 계속 기록할수록 개인별 데이터가 축적된다.

서비스가 추구하는 핵심 경험은 다음과 같다.

**기록 → 축적 → 비교 → 반복 패턴 발견 → 개인별 근거 강화**

사용자가 서비스를 오래 사용할수록 자신의 피부와 제품·성분 사이의 관계를 더 구체적으로 이해할 수 있도록 하는 것이 최종 목표다.
