# Security

> 문서 상태: 초안  
> 기준 문서: `docs/mainplan.md`

## 1. 보안 목표

이 서비스는 피부 사진, 피부 상태, 생활 요인 등 민감할 수 있는 개인 기록을 다룬다. MVP 단계에서도 다음 원칙을 지킨다.

- 필요한 데이터만 수집한다.
- 사용자의 데이터는 사용자 본인만 접근할 수 있어야 한다.
- OpenAI API key, Supabase service role key, 외부 데이터 API key는 Android 앱에 포함하지 않는다.
- AI 분석에는 필요한 최소 데이터만 전달한다.
- 제품 성분표, 샤워용품 라벨, 영양제 원료명 또는 영양정보 사진은 텍스트 추출에만 사용하고 저장하지 않는다.
- 사용자 지역 정보는 날씨 조회에 필요한 최소 범위로 저장한다.
- 진단, 치료, 원인 확정처럼 의료 서비스로 오해될 수 있는 표현을 피한다.

## 2. 인증 및 인가

### 인증

- 사용자 인증은 Supabase Auth를 사용한다.
- Android 앱은 로그인 후 Supabase access token을 저장한다.
- Backend API 요청 시 `Authorization: Bearer <token>` 헤더를 사용한다.
- Backend는 모든 보호 API에서 access token을 검증한다.
- 회원가입에서 Supabase Admin API가 필요하면 Backend에서만 호출한다.
- 해커톤 시연용 이메일 인증 우회는 Backend의 제한된 회원가입 API에서만 처리하며, Android에는 service role key를 넣지 않는다.

### 인가

- Backend는 검증된 사용자 ID를 기준으로 데이터를 조회하고 저장한다.
- 사용자는 자신의 제품 등록 정보, 사용 기록, 피부 기록, 사진, 분석 결과만 접근할 수 있다.
- Supabase PostgreSQL에는 RLS 정책을 적용해 사용자 소유 데이터 접근을 제한한다.
- Supabase Storage의 피부 사진도 사용자별 경로와 권한 정책을 사용한다.

## 3. 비밀키 관리

GitHub에 올라가면 안 되는 값은 `.gitignore`로 관리한다. 실제 키와 접속 정보는 로컬 `.env` 파일, 배포 환경 변수, Android의 로컬 설정 파일에만 둔다.

Android 앱에 포함하지 않는 값:

- `OPENAI_API_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- 외부 화장품 데이터 API key
- MFDS API key
- 기상청 API key
- 데이터베이스 비밀번호 또는 직접 접속 문자열

Backend 환경 변수로 관리하는 값:

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- `OPENAI_API_KEY`
- 외부 데이터 API key
- `MFDS_API_KEY`
- `KMA_API_KEY`

GitHub에 커밋하지 않는 파일과 값:

- `.env`
- `.env.*`
- `local.properties`
- OpenAI API key
- Supabase service role key
- Supabase anon key 실제 값
- Supabase database password
- PostgreSQL connection string
- 외부 화장품 데이터 API key
- MFDS API key
- 기상청 API key
- 배포 서비스 token
- 개인 계정 access token

예시 값은 `Backend/.env.example`에만 둔다. `.env.example`에는 실제 키를 넣지 않고 변수 이름과 빈 값 또는 더미 값만 기록한다.

현재 `.gitignore`에는 다음 항목이 포함되어야 한다.

```gitignore
.env
.env.*
!.env.example
local.properties
```

새로운 비밀키 파일이 생기면 코드를 작성하기 전에 먼저 `.gitignore`에 추가한다.

## 4. 데이터 분류

### 일반 데이터

- 제품명
- 브랜드
- 제품 종류
- 공개된 성분명
- 공개된 원료명 또는 영양정보 라벨 텍스트

### 사용자 개인 데이터

- 사용자가 등록한 제품 목록
- 오늘의 피부 기록
- 제품 프리셋
- 오늘 사용 제품 목록
- 생활 요인 기록
- 지역 설정과 날씨 스냅샷
- 분석 결과

### 민감하게 취급할 데이터

- 피부 사진
- 제품 성분표 사진
- 피부 고민
- 트러블, 붉음 등 피부 상태 기록
- 수면 시간 등 생활 요인
- 외출 시간
- 사용자 지역 설정

민감하게 취급할 데이터는 최소 수집, 접근 제한, 삭제 가능성을 기본 전제로 설계한다.

## 5. 피부 사진 정책

- 피부 사진은 PostgreSQL에 직접 저장하지 않고 Supabase Storage에 저장한다.
- PostgreSQL에는 사진 경로, 업로드 시각, 연결된 피부 기록 ID 등 메타데이터만 저장한다.
- 사진 파일 경로는 사용자 ID 기준으로 분리한다.
- 사용자가 피부 기록을 삭제하면 연결된 사진도 함께 삭제하는 정책을 우선 고려한다.
- MVP에서는 AI 분석에 사진 원본을 반드시 전달하지 않는다. 사진 기반 분석을 추가할 경우 별도 동의와 전송 범위를 명확히 한다.

### 제품 성분표 및 라벨 사진 정책

- 제품 성분표 사진은 피부 사진과 다르게 취급한다.
- 성분표, 샤워용품 라벨, 영양제 원료명 또는 영양정보 사진은 제품 등록을 위한 AI 텍스트 추출 요청에만 사용한다.
- 제출 사진 원본은 Supabase Storage, PostgreSQL, 로그에 저장하지 않는다.
- 저장 대상은 AI가 추출한 텍스트, 사용자가 수정/확정한 성분표 텍스트, 성분 매칭 결과뿐이다.
- 사용자가 확정하기 전 AI 추출 결과는 임시 결과로 취급한다.
- 공용 제품 DB에는 사용자가 최종 확인한 제품 정보와 성분 정보만 등록한다.

### 위치와 날씨 정보 정책

- Android에는 기상청 API key를 저장하지 않는다.
- 날씨 조회는 Backend가 수행한다.
- MVP에서는 정밀 GPS 좌표 대신 사용자가 선택한 지역명과 대표 ASOS 관측소 ID를 우선 저장한다.
- AI 분석에는 상세 위치 자체보다 기록일의 온도, 습도, 강수량, 풍속 등 환경 요약을 전달한다.
- 사용자가 지역 설정을 변경해도 과거 오늘 기록의 날씨 스냅샷은 당시 기록 근거로 보존한다.

## 6. AI 사용 원칙

AI는 사용자의 기록을 이해하기 쉬운 설명으로 바꾸는 역할을 한다.

AI에 전달할 수 있는 데이터:

- 제품 사용 날짜와 시각
- 제품명과 성분명
- 제품 등록 시 성분표 사진
- 피부 상태 점수
- 생활 요인
- 외출 시간과 날씨, 온도, 습도 등 환경 요약
- 사용자가 입력한 메모 중 분석에 필요한 내용
- 이전 분석 결과의 요약과 후보 성분 이름

AI에 전달하지 않거나 최소화할 데이터:

- 이메일
- 실명
- 전화번호
- 불필요한 사용자 식별자
- 분석에 필요하지 않은 사진 원본
- 저장이 필요하지 않은 성분표 사진 원본
- 정밀 위치 정보
- 전체 기간의 원본 피부 기록 전문

AI 응답은 다음 표현을 피해야 한다.

- 특정 질환을 확정적으로 진단
- 특정 성분이 문제의 원인이라고 단정
- 치료 방법, 처방, 복용 지시
- 영양제 복용 효과를 확정하거나 복용량을 지시하는 표현
- 데이터가 부족한데도 확정적인 결론 제시

분석 토큰과 개인정보 노출을 줄이기 위해 Backend는 최근 30일 기록을 중심으로 상세 evidence를 만들고, 전체 기간 기록은 성분별 노출 횟수와 개선/악화 동반 횟수 같은 압축 통계로 바꿔 AI에 전달한다.

## 7. 삭제 및 내보내기

MVP에서 우선 구현할 항목:

- 사용자가 직접 입력한 제품, 사용 기록, 피부 기록 삭제
- 피부 기록 삭제 시 연결 사진 처리 정책 정의
- 제품 제출 취소 시 임시 AI 추출 결과 삭제

향후 확장 항목:

- 전체 기록 내보내기
- 계정 탈퇴 시 사용자 데이터 삭제
- 분석 결과 삭제

## 8. 체크리스트

- Android에 서버 비밀키가 들어가지 않았는가?
- GitHub에 올라가면 안 되는 키와 설정 파일이 `.gitignore`에 포함되어 있는가?
- `.env.example`에 실제 키가 아닌 빈 값 또는 더미 값만 들어 있는가?
- 모든 보호 API가 JWT 검증을 거치는가?
- 사용자 ID를 클라이언트 입력값으로 신뢰하지 않는가?
- 사진은 Storage에 저장하고 DB에는 메타데이터만 저장하는가?
- 성분표 사진 원본이 Storage, DB, 로그에 저장되지 않는가?
- 샤워용품 라벨과 영양제 원료명 사진 원본도 Storage, DB, 로그에 저장되지 않는가?
- 제품 DB에는 사용자가 최종 확인한 성분 텍스트만 저장되는가?
- Android에 기상청 API key가 포함되지 않는가?
- AI 요청에 정밀 위치 정보 대신 필요한 환경 요약만 포함되는가?
- AI 요청에 불필요한 개인정보가 포함되지 않는가?
- 분석 결과에 진단, 치료, 원인 확정 표현이 없는가?
- `.env` 파일이 Git에 포함되지 않는가?
